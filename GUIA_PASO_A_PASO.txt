============================================

Este documento registra lo construido hasta ahora y el motivo de cada paso.

Proyecto_easy_receipt_analyzer.txt

OBJETIVO DEL PROYECTO
---------------------
Crear una aplicacion Android que ayude a controlar gastos a partir de tickets
de supermercado. El problema que quiere resolver es que los tickets pequenos
son incomodos de guardar y analizar manualmente.

El MVP futuro recibira una imagen de un ticket, extraera su texto con OCR,
interpretara los datos y guardara, como minimo, tienda, fecha, total y
productos.

ESTADO ACTUAL
-------------
Estamos en la fase inicial de interfaz con Kotlin y Jetpack Compose.
Todavia NO se ha implementado:

- Camara ni seleccion real de imagenes.
- OCR o ML Kit.
- Base de datos Room.
- Analisis de productos o gastos.
- Conexion a una API de IA.

1. CREACION DEL PROYECTO
------------------------
El proyecto se creo en Android Studio usando la plantilla Empty Activity.

Por que Empty Activity:
- Incluye una Activity inicial, Gradle y una configuracion funcional.
- Activa Jetpack Compose para crear la interfaz con Kotlin.
- Evita configurar un proyecto completamente vacio desde cero.

Por que no se anadio Gemini API:
- No es necesaria para el primer MVP.
- Primero se implementara el flujo local: imagen -> OCR -> texto -> parser.
- La IA se evaluara mas adelante, solo si aporta valor para tickets dificiles.

6. COMO FUNCIONA EL CAMBIO DE PANTALLA
--------------------------------------

En MainActivity.kt existe este tipo:

private enum class AppScreen {
    Home,
    AddReceipt
}

Un enum define un conjunto cerrado de opciones. Aqui solo hay dos posibles
pantallas: Home (inicio) y AddReceipt (anadir ticket).

La app guarda cual se esta mostrando con:

var currentScreen by remember { mutableStateOf(AppScreen.Home) }

- currentScreen contiene la pantalla actual.
- AppScreen.Home es el valor inicial.
- mutableStateOf permite que Compose observe los cambios.
- remember conserva ese valor mientras la Activity siga abierta.

Cuando se pulsa "Anadir un ticket", el boton ejecuta:

currentScreen = AppScreen.AddReceipt

Compose detecta el nuevo valor y vuelve a dibujar la interfaz. Entonces se
muestra AddReceiptScreen. El boton "Volver" realiza el cambio contrario:

currentScreen = AppScreen.Home

La seleccion de la pantalla se decide con:

when (currentScreen) {
    AppScreen.Home -> HomeScreen(...)
    AppScreen.AddReceipt -> AddReceiptScreen(...)
}

7. PIEZAS DE COMPOSE QUE APARECEN
---------------------------------

@Composable
    Marca una funcion que dibuja una parte de la interfaz.

Column
    Coloca elementos uno debajo de otro.

Text
    Muestra un texto.

Button y TextButton
    Crean botones. TextButton es un boton visualmente mas discreto; se usa
    para "Volver".

Modifier
    Ajusta el aspecto o comportamiento de un elemento. En este proyecto se
    usa para ocupar el ancho o alto disponible y aplicar margenes.

Spacer
    Deja espacio entre elementos. Por ejemplo, 16.dp significa 16 unidades
    de densidad independiente de pantalla.

Scaffold
    Proporciona una estructura base de pantalla y deja preparada la app para
    elementos futuros como barras superiores, avisos o botones flotantes.

@Preview
    Permite previsualizar una pantalla en Android Studio sin instalar la app.
    Hay una previsualizacion para la pantalla de inicio y otra para anadir
    ticket.

9. BASE DE DATOS LOCAL: ROOM
----------------------------
Se ha preparado Room, la biblioteca recomendada por Android para guardar datos
estructurados en una base de datos SQLite local. No necesita conexion a
Internet y los datos permanecen en el movil al cerrar la app.

Room se compone de tres piezas:

1. Entity: representa una tabla de la base de datos.
2. DAO: contiene las operaciones para consultar o guardar esa tabla.
3. Database: crea y mantiene la conexion con la base de datos.

Tambien se ha anadido un Repository. Su objetivo es evitar que las pantallas
hablen directamente con el DAO. Mas adelante sera el punto comun desde el que
la app guardara y leera tickets.

Archivos creados:

app/src/main/java/com/easyreceiptanalyzer/data/local/ReceiptEntity.kt
    Define la tabla "receipts". Cada objeto ReceiptEntity sera una fila.

app/src/main/java/com/easyreceiptanalyzer/data/local/ReceiptDao.kt
    Define las operaciones insert, observeAll y findById.

app/src/main/java/com/easyreceiptanalyzer/data/local/AppDatabase.kt
    Crea una sola instancia de la base de datos local llamada
    easy_receipt_analyzer.db.

app/src/main/java/com/easyreceiptanalyzer/data/ReceiptRepository.kt
    Ofrece una capa sencilla para guardar, obtener y observar tickets.

DATOS DE UN TICKET
------------------
Por ahora cada ticket puede almacenar:

- id: identificador unico, creado automaticamente por Room.
- storeName: nombre de la tienda.
- purchaseDate: fecha de compra como marca de tiempo; inicialmente puede no
  conocerse.
- totalCents: importe total en centimos; se usa Long y no Double para evitar
  errores de redondeo con dinero.
- rawText: texto completo obtenido del OCR; inicialmente puede no conocerse.
- createdAt: momento en que se creo el registro en la app.

La tabla aun no tiene productos. Se agregaran cuando el OCR y el parser puedan
extraerlos de forma fiable.

CONCEPTOS NUEVOS
----------------
Hilt (Dependency Injection)
  - Framework de DI para Android basado en Dagger
  - @HiltAndroidApp: Anotacion en Application class para inicializar Hilt
  - @AndroidEntryPoint: Anotacion en Activity para habilitar inyeccion
  - @Module: Clase que define como proporcionar dependencias
  - @InstallIn: Define el componente Hilt donde se instala el modulo
  - @Provides: Metodo que indica como crear una dependencia
  - @Singleton: Asegura que solo exista una instancia de la dependencia
  - @HiltViewModel: Permite inyectar dependencias en ViewModels
  - @Inject: Solicita a Hilt que proporcione la dependencia

Photo Picker (Seleccion de Imagenes)
  - API moderna de Android para seleccionar imagenes/videos
  - ActivityResultContracts.PickVisualMedia: Contract para Photo Picker
  - PickVisualMediaRequest: Configura que tipo de media seleccionar
  - rememberLauncherForActivityResult: Integra el launcher en Compose
  - No requiere permisos de almacenamiento (mejor privacidad)
  - Automaticamente usa ACTION_OPEN_DOCUMENT como fallback en Android < 13

Coil (Carga de Imagenes)
  - Libreria moderna para cargar y mostrar imagenes en Compose
  - AsyncImage: Componente Compose para cargar imagenes asincronamente
  - Maneja caching, redimensionamiento y errores automaticamente
  - Optimizado para Compose y corutinas

ViewModel en Compose
  - hiltViewModel(): Funcion para obtener ViewModel inyectado por Hilt
  - collectAsState(): Convierte Flow a State observable por Compose
  - Separacion de logica de negocio de la UI
  - Sobrevive a recomposiciones de Compose

Testing con Mockito y Coroutines
  - Mockito: Framework para mockear objetos en tests
  - mockito-kotlin: Extensiones de Mockito para Kotlin
  - @Mock: Crea un mock de una clase
  - when().thenReturn(): Configura comportamiento del mock
  - verify(): Verifica que se llamo a un metodo del mock
  - runTest: Funcion para ejecutar tests con corutinas
  - flow.first(): Obtiene el primer valor emitido por un Flow

DECISIONES DE DISEÑO
--------------------
- Photo Picker en lugar de GetContent: mas moderno, mejor UX, sin permisos
- Coil en lugar de URI directa: mejor rendimiento, caching automatico
- Hilt en lugar de DI manual: arquitectura escalable, estandar de la industria
- Java 17 en lugar de Java 11: requerido por Hilt moderno y Compose
- Módulos por feature en lugar de modulo unico: mejor organizacion futura
- Pruebas unitarias desde el principio: mejor calidad, detectar bugs temprano
